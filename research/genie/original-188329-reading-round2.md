다섯 갈래를 따로 읽고, 갈래마다 다른 에이전트가 원본 디스어셈블과 엔진 소스를 다시 열어 반박을 시도했다. 여기에는 **검증에서 살아남은 것만** 적는다. 전체 보고와 검증표는 작업 폴더의 `re-kit\re-reading-round2.tar.gz`(`out_r1`~`out_r5`, 각 `*.md`와 `verify.md`)에 있다. 아무것도 실행해 보지는 않았다: 엔진에 넣고 원본 기록과 대조해야 확정이다.

## R1. 유닛 갱신 순서와 예약 명령 (정찰병 3틱 지연의 원인)

주소: 유닛 갱신 `0x114c0f0`(동작 목록 `0x11398c0` → 명령 검사 `0xd443f0` → 차례 검사 `0x1606aa0` → AI 가상 `+0x20` = `0xd42a00`), 명령 실행 `0xd384f0`(부르는 곳은 `0xd4445a` 하나), 알림 정리 `0xd38990`, can_order `0xd28660`, 그룹 검사 `0x10dd870`. 유닛 AI 기본 가상표 `0x324a268`(`+0x38` 알림 `0xd30c40`, `+0x230` `0xd37140`, `+0x238` `0xd33c40`, `+0x240` `0xd31a30`, `+0x248` `0xd31d50`).

## R2. Hunt·MoveTo

- 동작 목록: `0xb8ae30`은 맨 앞 동작의 코드를 그대로 돌려주고, 유닛 쪽 `0x11398c0`이 코드 1·3에서 맨 앞을 뺀다.
- **D1**: Hunt 상태 4에서 MoveTo 코드 4/5, 예약 명령 수 > 0(부호 있는 비교) → `set_target(0)`, `set_state(1)`, 0 반환. 다음 갱신에서 사람 선수는 `set_state(2)` 뒤 1을 돌려주고 그때 빠진다. 엔진 `lost_on_the_way`는 항상 그 점으로 걷는다.
- **D8**: 반납 뒤 목표가 없을 때 가축은 검색 세 번(매번 새 검색). (a) 상태 5, 반납 장소 기준, 최선 거리의 정수 절단 `d`도 받는다. (b) 없거나, `gap(유닛, a) < R`도 `(float)(2*d) < R`도 아니면: 상태 5, 유닛 기준. (c) 없거나 `gap(유닛, a) >= R`이면: 상태 제한 없이 반납 장소 기준. 둘 다 엄격한 `<`. `2*d < R`로만 남은 동물은 (c)가 항상 바꾼다. 아무것도 없으면 점의 x나 y가 −1일 때 `set_state(2)`, 아니면 `set_state(11)`. 엔진은 검색 한 번.
- 검색 `0xd22c20`: 기준 객체가 있으면 거리는 `0x124d8d0`(외곽 간 거리). class 65이고 양 ≤ 0이면 건너뛴다. 상태 값은 날것 그대로 5로 구현한다.
- **D8b**(주민 알림 처리기 쪽의 같은 세 번 검색): 알림 0x1fb·0x1fc·0x202가 같은 블록이고 `[ai+0x44] == 0x265`여야 하며, 알림 자신의 class가 58일 때만이다.
- **D9**: MoveTo에 대기가 없다. 상태 2 → 3 즉시, 걷기 결과 1 → 같은 갱신에서 `set_state(13)`. 엔진 `give_up`은 항상 실패로.
- N1: 주민 AI(가상표 `0x3245908`) 슬롯 `0x1b0`(`0xcf9c60`)이 class 10을 kind 5로 바꾼다. N2: `set_state(3)`에 class 10 예외가 없다(타이머 −10.0).

- **N1 자원 검색이 새로 쓰였다**: 래퍼 `0xd23bf0`, 본체 `0xd19f60`, 모서리 규칙 `0xd1c390`(`byte[0x42bde58] == 0`일 때), 한 타일 씨앗은 `0x12426a0 == 1`도 통과해야 한다. `0x107af40`은 유닛의 남은 경로 길이를 `dist * 2.5 + 3.5`와 비교한다.

## R4. 틱당 걷기 `0x1210f60`

엔진 `movement/`에는 188329 스위치가 없다. 아홉 중 여덟이 통과했다.

- **D1** 종류 2 인계는 class 0x13이 아니면 맨 위 단계까지 푼다(엔진은 한 단계만). 첫 상위 경로가 순환이면 풀지 않는다.
- **D2** `0x106ee30`은 항상 줄인다. 유형 ≥ 1 단계가 마지막 경유점에 못 미치면 REACHED와 시도 10회.
- **D3** 새 블록은 경로 길이를 재지 않고 만든 시각도 쓰지 않는다(`created = now`를 넣지 말 것). 결과 1, 3, ≥ 6을 남긴다.
- **D4** 목표가 있고 경로 있는 단계가 전부 마지막 경유점이면 목적지는 (목표 x, 0, 목표 y). 무시 목록과 끝 간격은 여전히 경유점 기준.
- **D5** 결과 3이면 AI `+0x38`을 (유닛 id, 유닛 id, `0x21e`, −1, −1, −1)로 부른다. 조건은 D4의 "전부 마지막 경유점" 플래그.
- **D6** 시도 > 0이면 대기 0.1과 정지(줄 `0x192d`)가 마지막 경유점 검사보다 먼저다. D2와 합치면 보통 걷기의 "경로 없음"은 매번 멈췄다 간다.
- **D7** 충돌 처리에서 건너뛰는 것은 같은 그룹 구성원뿐이고 class 검사가 없다(엔진은 class 3·27·39·52를 뺀다).
- **D8** class 0x43 검사(`0x1213d16`). 엔진에 class 67 역할이 없다.
- D9(타일 경로 결과 코드 거르기)는 타일 탐색기 `0x1057a40`을 읽기 전에는 믿지 않는다. 지금 `0x10527c0`과 선택적 `0x10533b0` 두 번 탐색을 한다.

## R5. 생산·생성 위치

- **D1 고칠 것**: `spawn_point_188329`의 float 순서. 원본은 `off + half`를 먼저 만들고 `step*n + (off + half)`다. 엔진은 `(step*n + off) + half`로 되어 있다(바깥 고리 n ≥ 1만 영향).
- **D2 경로 모드**(미구현): 경로는 **집결점 → 건물 중심**이다(엔진 주석이 반대로 적혀 있다). 점은 출발→도착 순, `path_mode = 개수 > 1`. 끝에서 두 번째 점의 타일을 `sx = (int)P.x − ox`로 잡아 격자 안으로 자르고, 통과 불가여도 씨앗으로 넣는다. 통과 불가 타일에서 시작하면 통과 가능한 타일을 만날 때까지 통과 불가 타일로 퍼진다(판정을 격자 좌표로 부르는 원본의 버릇까지). 정렬은 (두 번째 걸음 수, 집결점 거리) 안정 정렬. 첫 후보의 걸음 수가 10000이면 그 고리를 버리고, 다 실패하면 거리만으로 고리 0부터 다시 한다.
- **D3** 통과 판정은 성문 타일(0x500)을 동맹이면 통과로 본다. **D4** 상태 10의 5.0초 재시도. **D5** 집결점이 건물 자신일 때의 줄 위치(건물 AI 가상표 `0x32469c8` 슬롯 0x218·0x220).
- 훈련 호출은 (−1, −1), 플래그 0을 넘긴다. 훈련 진행과 출현 틱은 엔진과 같다.
