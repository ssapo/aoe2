# AoE2 DE 길찾기 분석 노트

대상: `AoE2DE_s.exe` 빌드 101.103.57257.0 (PE 시각 `0x6acf93a9`, 이미지 크기 `0x4f24000`).
방법: 실행 중 메모리 덤프(코드 영역 복호화 상태)를 Ghidra/capstone으로 읽음. 게임을 돌려 대조한 검증은 아직 없음.
주소는 모두 RVA. 소스 파일 흔적: `Aoc\Source\Game\Map\PathingSystem.cpp`.

## 0. 전체 구조

탐색기 3종.

| 이름 | 진입 | 좌표 | 성격 |
|---|---|---|---|
| A 타일 탐색 | `0x1078d60` | 타일 정수, 최대 480×480 | 거리 제곱을 예상 비용으로 쓰는 A* 변형 (탐욕적) |
| B 구역 탐색 | `0x1057a40` → `0x10527c0` → `0x1052f60` | 1/2/4/8타일 칸의 4단계 격자 | 4방향 A*, 유클리드 거리 |
| C 정밀 탐색 | `0x1078690` → `0x107f7a0` | 고정소수점 (좌표 × 2^22) | 직진 + 장애물 사각형 둘레 따라가기 |

진입 함수: `0x1077e70`, `0x1078320` (B 객체 있으면 B, 없으면 A), `0x107a5e0` (B → C(거리 ≤ 10) → A(거리 ≥ 1) 순서), `0x107a390` (C 계열 다른 질의).
A의 전역 객체: `0x3db3330`. PathingSystem 전역 포인터: `0x4357fe0` (+8 = C용 객체, +0x380 = 큰 유닛용 탐색 객체, +0x98 = 타일 비트맵 객체).

## 1. 타일 탐색 A (`0x1078d60`)

- 격자 인덱스 `x*480 + y`. 비용 배열 `this+0x38420` (int), 상태 배열 `this+0x20` (byte), 힙 `this+0x119420` (8바이트 항목: u16 x, u16 y, int 키; 1번부터 사용, 0번은 보초 키 `0x88ca6c00`), 힙 개수 `this+0x2db428`, 탐색 번호 `this+0x2db430` (탐색마다 +8, 0xF0 넘으면 상태 배열을 0xFF로 초기화).
- 상태 바이트: 위 5비트 = 탐색 번호, 아래 3비트 = 들어온 방향.
- 방향 번호: 0 `(-1,-1)`, 1 `(0,-1)`, 2 `(+1,-1)`, 3 `(+1,0)`, 4 `(+1,+1)`, 5 `(0,+1)`, 6 `(-1,+1)`, 7 `(-1,0)`. 확장도 이 순서.
- 건너뛰는 방향 표 (`0x329ce88`, 들어온 방향별 비트마스크): `38 70 E0 C1 83 07 0E 1C 00`. 들어온 방향의 정반대와 양옆 3개를 제외. 시작 타일(8)은 전부 확장.
- 이동 비용: 직선 4, 대각선 8. 예상 비용 `16*(dx²+dy²)`. 방향이 바뀌면 +1. 키 = 누적 비용 + 예상 비용.
- 대각선은 사이의 직각 두 타일이 모두 비어야 함.
- 이미 본 타일은 새 키가 더 작을 때만 갱신 후 재삽입.
- 힙 삽입(`0x107ae70`)은 `<=` 비교로 올림: 동점이면 새 항목이 위.
- 목표 영역에 들어가는 타일은 키 0으로 넣고 즉시 종료.
- 한도: 확장 횟수 > `직선거리 * 설정값/100` (설정값 전역 `0x435d6a0`, 실행 중 7500 → ×75) 또는 > 20000이면 중단. 일부 플레이어는 ×25. 중단 시 목표에 가장 가까웠던 타일까지의 경로 사용.
- 탐색 전 자신, 같은 묶음 유닛(최대 255), 목표 개체를 통과 판정에서 임시 제외.

### 경로 되짚기 (`0x1077870`)
- 힙 맨 위 타일에서 들어온 방향의 반대로 시작 타일까지 이동.
- 방향이 바뀌는 타일만 경유점. 목표 쪽 첫 타일과 시작 타일은 항상 포함.
- 경유점 좌표 = 타일 + 0.5. 목록 맨 앞에 삽입하므로 최종 순서는 시작 → 목표.
- 경유점 12바이트: x(float), 유닛 유래 값(높이 추정), y(float).

### 통과 판정
- 타일 비트맵: 타일당 8바이트, 인덱스 `y*너비 + x` (객체 `+0x98` 배열, `+0xa0` 너비).
- 아래 8비트 = 지형 통과 분류, 비트 8~13 = 개체 종류 코드(`0x500` = 소유자에 따라 열리는 타일, 성문 추정), 비트 16~22 = 소유 플레이어.
- 유닛 마스크 = `표[지형 제한 번호] ^ 0xFF`. 두 번째 마스크는 여기에 `0x4000` 추가.

## 2. 구역 탐색 B

- 칸 2바이트. 첫 바이트: 1=위(y−1), 2=왼(x−1), 4=오른(x+1), 8=아래(y+1) 통로, 0x10 열림, 0x20 닫힘. 둘째 바이트: 0x20 이 단계에서 사용, 0x40 더 쪼개짐, 0x10 목표 칸.
- 단계 3(8×8)부터 내려가며 시작 칸 결정. 이웃 순서: 왼, 오른, 위, 아래. 크기가 다른 이웃은 단계 올림/내림(`0x1051150`).
- 비용: 칸 중심 간 유클리드 거리(float). 예상 비용: 목표까지 유클리드 거리.
- 직각으로 꺾일 때는 조부모 칸에서 직접 잰 거리로 비용 계산.
- 결과 코드: 1 완전, 2 부분(예상 비용 최소 노드), 4 없음.
- 조기 종료: 출발-목표 거리 ≤ 10, 남은 예상 거리 ≤ 5, 확장 횟수 ≥ 거리×10.
- 진입 함수는 경로 길이 < 35일 때 두 번째 탐색을 돌려 더 나은 쪽 선택. 첫 경유점에서 거리 100 넘는 지점 기준 재탐색 보정 있음.

## 3. 정밀 탐색 C

- 좌표 정수 = 실제 × 4,194,304. 타일 1칸 = `0x400000`.
- 탐색 창 = 출발·도착 경계 사각형 ±4타일, 맵 가장자리는 반지름만큼 안쪽.
- 장애물 = 축 정렬 사각형(16바이트). 충돌 검사 시 유닛 반지름만큼 부풀림.
- 통과 불가 타일은 같은 줄의 연속 구간을 가로로 합쳐 임시 사각형으로 등록(`0x1082670`).
- 출발점이 장애물 안이면 변 위 최근접점, 원-변 교점, 모서리를 탈출 후보로 사용(`0x107e820`).
- 직진 검사: 선분이 지나는 칸을 순서대로 밟으며 칸별 장애물과 선분-사각형 교차 검사(`0x1084770`, `0x1084210`). 22비트 고정소수점 비율.
- 막히면 장애물 묶음 다각형의 꼭짓점을 양방향으로 따라감. 꼭짓점별 최소 비용 기록(초기값 −4194304).
- 비용: 자유 이동은 유클리드 거리, 둘레 이동은 `max(|dx|,|dy|)`.
- 막힌 선분 재검사에 1.1배 연장점(`0x466666`) 사용.
- 도착 판정: 목표 사각형까지의 초과분 제곱합 ≤ 사거리².
- 유닛 반지름 > 0.5이거나 특정 기능이 꺼져 있으면 C 대신 다른 탐색 객체(`0x1060d90`) 사용.

## 4. 유닛 이동에서의 사용 (`0x1210f60`, 일부만 읽음)

- 유닛은 큰 줄기 경로(공유 객체, 현재 경유점 번호 `경로상태+0x24`)와 자기만의 단거리 경로를 따로 가짐.
- 매 틱 대기 타이머(`경로상태+0x34`)에서 경과 시간을 빼고, 0보다 크면 이동하지 않음.
- 다음 경유점까지 거리가 10 이하이면 C로 단거리 경로를 만듦. 목표 사거리는 0.1 줄여서 전달.
- C가 실패하거나 경로 길이가 0에 가까우면 조건부로 A로 대체.

## 5. 아직 안 읽은 것

- C: 다각형 묶기(`0x1082ff0`), 둘레 노드 생성(`0x1081ab0`) 세부.
- B: 경유점 다듬기(`0x1053bb0`), 지도 갱신.
- 큰 유닛용 탐색(`0x1060d90`).
- 유닛 이동 함수의 나머지(틱당 이동량, 충돌 시 대기·재탐색 규칙).
- 묶음 이동(`0x10ef890`), 이동 동작(`0x1114a30`, `0x1109d70`).
