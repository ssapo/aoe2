# AoE2 리플 분석 — ssapo

ssapo 계정의 1v1 경기 기록과 공개 리플을 자동 수집하는 개인용 웹앱.

- 게임 서버 프로필 ID: `26260702`
- AoE2 Insights 사용자 ID: `13810994`
- 프로필: https://www.aoe2insights.com/user/13810994/

두 ID는 서로 다름. 이전에 공유한 경기 `516293031`, `516495787`에서 ssapo의 Insights 사용자 링크와 리플 다운로드 profileId를 확인했고, 게임 서버 API에서 닉네임 ssapo를 재확인함.

계정 선택·가입·프로필 입력 없음. 접속하면 저장된 ssapo 경기 목록을 바로 표시.

## 배포

1. GitHub에 `ssapo/aoe2` 공개 저장소 생성. 기본 브랜치 `main`.
2. 이 폴더의 파일·폴더를 저장소 최상위에 업로드. `.github/workflows/update.yml` 포함. ZIP 자체를 업로드하는 방식은 작동하지 않음.
3. `Settings → Pages → Source`를 **GitHub Actions**로 설정.
4. `Actions → Collect matches & deploy → Run workflow` 실행. 계정 입력 불필요.
5. 배포 성공 후 Pages에 표시된 주소 확인.

운영 주소: https://ssapo.github.io/aoe2/ (GitHub Pages 배포 완료).
`.aoe2`는 공개 DNS의 등록된 최상위 도메인이 아니므로 `ssapo.aoe2` 사용 불가.

공개 저장소의 GitHub Pages·표준 Actions runner 기준 무료. 유료 AI API·도메인·별도 서버 미사용. 게임 닉네임과 분석 결과는 공개됨. 채팅·원본 리플·Steam ID·토큰은 게시하지 않음.

## 동작

- 매시 17분·47분에 새 경기 확인. 실행 지연·누락 가능.
- 본인 계정의 1v1 완료 경기만 수집. 최대 200개 저장.
- 실행당 새 경기·실패 경기 최대 5개 분석. 실패한 경기는 최대 3회 재시도.
- 경기 선택 시 명령 기록과 한국어 피드백 표시. 리플 다운로드·Insights 링크 제공.
- 열린 페이지는 2분마다 저장된 결과 갱신. 새로고침은 저장 결과 조회. **지금 수집**은 GitHub 수동 실행 화면을 열고 결과 자동 확인을 시작. GitHub에서 `Run workflow` 메뉴와 실행 버튼을 눌러야 실제 수집 시작.
- 수집 오류 시 이전 성공 데이터 유지.
- 60일간 저장소 활동이 없으면 예약 실행 중지 가능. Actions에서 재활성화.

## 분석 범위

지원: 양측 건설·생산·연구 명령 전체 타임라인, 시대 전환 **최초 명령 시점**과 시스템 알림의 **실제 시대 도달 시각**, 파서 eAPM, 1v1 상대 비교. 시대업 클릭 당시의 누적 유닛 생산 지시량과 직전 2분의 생산 지시량, 유닛·건물·전체 연구 지시의 최초 시각·횟수 제공.

명령은 실제 완료와 다름. 취소·자원 부족·파괴·게임 상태를 시뮬레이션하지 않음. TC 유휴시간·실제 자원·교전 손실·패인의 인과관계는 계산하지 않음. 시대 전환이 늦다는 사실만으로 실수라고 단정하지 않음.

공개 리플 미제공·만료·패치 호환 실패 시 기본 경기 기록만 표시. AI전·비공개 경기와 과거 모든 경기의 확보는 보장하지 않음.

## 로컬 실행

Python 3.12 이상 권장. 별도 가상환경에서 실행.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/patch_parser.py
python -m unittest discover -s tests -v
node --test tests/test_collection_watch.cjs
python scripts/collect.py --limit 5
python -m http.server 8000 --directory site
```

브라우저: `http://localhost:8000`. 방문자의 Python 설치 불필요. 배포 후 분석은 Actions에서 처리.

`mgz==1.8.51` 호환 문제는 upstream PR #139의 빠른 파서 수정으로 대응. 고정 버전을 확인하고 적용하며 원격 코드를 실행할 때마다 다운로드하지 않음. 출처·라이선스는 `THIRD_PARTY_NOTICES.txt` 참고.

## 파일

- `site/`: HTML·CSS·JS·수집한 보고서 JSON
- `config.json`: 고정 계정·1v1 필터
- `scripts/collect.py`: 수집·분석
- `scripts/berry.py`: 열매 군락과 주민 재배치 명령에 기반한 전환 구간 추정
- `scripts/details.py`: 실제 시대 도달 알림, 시대업 클릭 당시 생산 지시량, 양측 전체 명령 비교
- `scripts/review.py`: 시간대별 수치 집계, 양측 근거 기반 진단, 개인 과거 중앙값
- `scripts/patch_parser.py`: 파서 호환 수정
- `.github/workflows/update.yml`: 수집·배포 예약
- `tests/`: 수집 오류·프로필 ID 구분·압축파일·명령 시점·데이터 보존 검사

별도 `SSAPO_AoE2_preview.html`은 저장 시점의 경기 데이터를 포함한 단일 HTML. 로컬 파일은 최신 결과를 자동 수집하지 않음. 자동 갱신은 전체 소스를 배포한 사이트에서 동작.

#### 버튼으로 수동 수집

- **지금 수집** 버튼: GitHub Actions의 기존 `workflow_dispatch` 실행 화면을 새 탭으로 열고, 돌아왔을 때 새 결과를 자동 확인. GitHub 로그인 및 저장소 쓰기 권한이 있는 계정에서 `Run workflow` 메뉴 → `Run workflow` 실행이 필요. 사이트 버튼 클릭 자체를 수집 시작으로 표시하지 않음.
- 30분 예약 수집과 기존 새로고침 동작 유지. 별도 서버·유료 서비스·방문자에게 노출하는 GitHub 토큰 추가 없음.
- 작은 `data/status.json`을 15초 간격으로 최대 10분 확인. 버튼을 누른 시점에 상태 기준값을 새로 읽고, 이후 실제 `last_checked_at` 변경이 게시돼야 보고서를 다시 읽음. 상태 확인 중 매번 전체 경기 보고서를 다운로드하지 않음.
- 새 경기가 없어도 수집 확인 시각이 바뀌면 새 결과 확인으로 표시. 예약 실행 결과와 수동 실행 결과를 임의로 구분하지 않음. 오류가 게시되면 기존 분석을 유지한 채 오류 표시. 네트워크·보고서 조회 실패는 재시도하며 완료로 표시하지 않음.

### 시대업 클릭 당시 주민 정보와 분석 범위 확장

- 사용자 요청: 각 시대업 클릭 당시 실제 주민 수와 승패 복기에 필요한 정보 확대.
- 현재 파서는 게임 상태를 재생하지 않으므로 실제 주민 수를 확정할 수 없음. 실제 생존 주민 수 필드는 `null`로 유지하며 UI에 허구의 숫자나 미측정 행을 추가하지 않음. 초기 주민 + 생산 지시량을 실제 주민 수로 계산하지 않음.
- 대신 별도 **주민 생산 지시량 (누적)** 표시. 클릭 이전 양수 `amount`의 합이며 시작 주민을 포함하지 않음. 생산 대기·재지시·취소·실패·자원 부족·인구 제한·사망·전향을 반영하지 않으므로 실제 생산·생존 수와 다름. 수량이 판독되지 않은 주민 명령이 있으면 확정 숫자를 표시하지 않음.
- 같은 타임스탬프라도 시대업 명령 뒤에 기록된 생산 지시는 해당 클릭의 누적량에서 제외. 재지시가 있어도 최초 클릭 스냅샷은 유지.
- 시대 도달은 `match.uptimes`의 해당 플레이어 시스템 알림으로 확인. 고정 연구시간을 더해 도달을 만들어내지 않음. 알림이 없는 시대는 도달 시각을 비워둠.
- 시대업 클릭 직전 120초의 유닛별 생산 지시량, 클릭 이전의 다른 유닛 생산 지시량 비교. 봉건·성주·왕정 모두 기록이 있는 경우 제공.
- 양측 유닛별 생산 지시량·최초 시각, 모든 경제·군사 연구 지시 시각·횟수, 건물별 첫 건설 지시·횟수를 접이식 비교표로 제공. 기존 상위 24종·초반 100개 제한과 별개로 전체 건설·생산·연구 타임라인 보관.
- 승패 복기 카드는 양측 도달 알림이 모두 있을 때 실제 도달 시각을 우선 비교. 생산 지시량이나 eAPM을 승패 원인으로 단정하지 않음.
- 분석 개정은 5. 이전 성공 분석의 개정이 오래된 경우 실행 예산 안에서 재분석. 다운로드·파싱 실패 시 기존 성공 분석 보존, 개정별 3회 시도 제한.
- 정확한 시점별 주민 수·유휴시간·자원별 보유량·교전 사상자·자원 채집량은 추가 게임 상태 수집 또는 게임 엔진 재생이 필요. 현재 무료 GitHub 정적 사이트에 해당 값을 자동 제공하는 것으로 오해하지 않도록 명시.
- 근거: [mgz 파서 FAQ](https://github.com/happyleavesaoc/aoc-mgz#frequently-asked-questions). 실제 화면 수집과 리플 명령을 결합하는 사례: [AoE2 Squire](https://github.com/chris-h-sg/aoe2-squire#developer-guide). 별도 앱 설치나 유료 서비스 연결은 수행하지 않음.

### 열매 작업 전환 추정 기준

- 초기 맵의 열매 덤불 개체 ID와 좌표를 사용. 서로 6타일 이내에 연결된 덤불을 같은 군락으로 묶음.
- 시작 주민 또는 경제 건설 명령으로 주민 역할이 확인된 개체의 명시적 명령만 사용. 선택 생략 명령을 추측해 채우지 않음.
- 열매를 대상으로 지시받은 같은 주민이 이후 나무·금·돌 대상 지시 또는 경제 건설 지시를 받는 시각을 추적.
- 열매 지시 이후 최소 30초가 지난 재배치만 후보로 사용. 45초 안에 서로 다른 주민 2명 이상이며 확인된 해당 군락 작업자의 60% 이상이 모이면 전환 구간 후보로 표시.
- 후보가 여러 개면 전환 인원이 가장 많은 구간을 택하고, 인원이 같으면 마지막 구간을 사용.
- 표의 `5/5명`은 확인된 열매 작업자 5명 중 전환 지시가 확인된 5명이라는 뜻. 실제 작업자 전체를 뜻하지 않음.
- 열매가 남은 상태에서 의도적으로 재배치했을 수 있음. 실제 채집 시작·종료·고갈, 주민 현재 위치, 명령 실행 완료는 확인하지 않음. 중간 자동 작업과 이동이 누락될 수 있음.
- 양측 모두 단체 전환 근거가 부족하면 해당 행을 생략. 한쪽만 확인되면 다른 쪽은 근거 부족으로 표시. 빈 정보를 임의의 시각으로 채우지 않음.
